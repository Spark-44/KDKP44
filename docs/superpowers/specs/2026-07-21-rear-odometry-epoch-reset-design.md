# 后轮里程坐标周期重置设计

## 问题与证据

录制模式在等待开始期间持续采样后轮编码器，以便显示距离诊断；这些样本同时进入姿态里程队列。开始录制时，路线坐标被重置到原点，但待消费的里程队列没有被清空。因此，开始前的移动会在新路线的第一次 `update_state()` 中被计入。

`records-2026-07-21-17-20-50.json` 显示，录制开始前累计里程为 `-7888 pulse`，即 `-2.982 m`。新路线第 0 点为 `(0, 0)`，第 1 点随即跳到约 `(-0.04, 2.98)`，随后实际向前移动的点又沿相反方向返回。Run 模式会追逐这个错误的首段目标，因此一开始就出现大幅左转。

## 设计

后轮驱动模块增加一个“丢弃待消费里程样本”的接口。该接口在关中断保护下重新初始化姿态里程队列，但必须保留：

- 累计编码器脉冲与距离诊断；
- 当前编码器基准计数；
- 速度采样窗口、速度 PID 状态与电机输出；
- 编码器方向和每脉冲距离标定。

在两个新的坐标周期边界调用该接口：

1. `portion2_record_begin_route()` 建立录制原点后、写入首个路线点前；
2. `portion2_run_task()` 初始化所选路线、建立 Run 原点时，在首次轨迹状态更新前。

这样，等待期间的移动仍能显示在累计距离诊断中，但不会进入新录制路线或新一轮 Run 的局部坐标。

## 测试与验收

增加静态回归检查，验证：

- 后轮驱动头文件公开队列丢弃接口；
- 实现使用中断保护清空姿态里程队列；
- 录制和 Run 两个坐标周期入口均调用该接口；
- 原有后轮驱动 Python 测试和相关 PowerShell 检查继续通过。

修复烧录后需要删除当前错误路线并重新打点。新日志中第 1 个记录点应距 `(0, 0)` 约一个正常记录步长，不再出现约 2.98 米的反向跳变；Run 起步应先沿录制的直线路段行驶。
